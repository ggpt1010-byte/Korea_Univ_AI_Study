# AI개발모임

모임원이 만든 AI 프로젝트를 올리고 서로 써보는 사이트입니다. 빌드 과정이 없는 정적 사이트라서 GitHub Pages에 그대로 올라갑니다.

## 구성

- `index.html` 결과물 목록, `project.html` 결과물 상세, `submit.html` 결과물 등록, `privacy.html` 개인정보 안내, `me.html` 내 정보(로그인한 계정으로 올린 결과물)
- `groups.html` 그룹 들어가기(방 목록 #1부터, 방 만들기), `group.html` 방 화면(제목과 설명, 비공개 결과물, 공개 결과물, 검증)
- `assets/manager.js` 예상 가치(평가 금액, 개선 시 예상 금액)와 매니저 기능, `estimate.html`은 예전 주소를 `submit.html`로 넘기는 페이지
- `assets/config.js` Supabase 주소와 공개 키, 구글 로그인, 피드백 설정을 모아 둔 곳
- `assets/db.js` Supabase 연결, `assets/vendor/supabase-2.99.3.js` Supabase 라이브러리(그대로 복사해 둔 것)
- `supabase/schema.sql` 데이터베이스 표, 읽기 규칙(RLS), 서버 함수. Supabase SQL Editor에서 실행
- 모든 HTML은 `assets/` 파일을 `?v=날짜`를 붙여 불러요. GitHub Pages는 파일을 10분쯤 브라우저에 저장해 두기 때문에, 여러 파일을 함께 바꾼 뒤에는 이 값을 새 날짜로 바꿔야 옛 파일과 새 파일이 섞여 화면이 비는 일이 없어요.
- `data/projects.json` 직접 넣어 둔 결과물 (지금은 예시)
- `shots/` 공개 결과물 체험 링크의 첫 화면 이미지 (자동으로 갱신)
- `scripts/capture.mjs` 첫 화면을 찍는 스크립트

## 데이터와 보안 (Supabase)

데이터는 Supabase(Postgres)에 있고, 사이트는 **공개 키(publishable/anon)만** 씁니다. secret/service_role 키는 사이트나 저장소에 절대 넣지 않습니다.

- **읽기**: 표마다 읽기 규칙(RLS)이 있습니다. 비공개 결과물과 방의 검증 기록은 그 방 멤버(와 올린 사람)에게만 내려갑니다. 방 비밀번호 값(`group_secrets`)과 조회 기록 원본(`views`)은 아무도 직접 읽을 수 없습니다.
- **쓰기**: 표를 직접 고치는 권한은 없고, `submit_project`, `create_group`, `join_group`, `leave_group`, `set_group_password`, `vote`, `like_project`, `record_view`, `record_value` 함수로만 씁니다. 함수가 서버에서 로그인 계정, 멤버 여부, 방장/매니저 여부를 확인합니다.
- **로그인**: 구글 로그인 버튼이 받은 ID 토큰을 `signInWithIdToken`으로 Supabase에 넘깁니다. Supabase가 토큰을 구글에 확인합니다. 계정 값(`g` + 16자리)은 예전과 같은 계산(`sha256('korai-account:' + 구글 계정 번호)`)을 서버가 `auth.identities`에서 직접 해서 흉내 낼 수 없습니다.
- **방 비밀번호**: bcrypt 값만 저장하고 서버가 확인합니다. 맞히면 그 계정이 `group_members`에 들어가서, 다음부터는 로그인만 하면 됩니다. 10분에 10번까지 틀릴 수 있습니다. 방장은 방 화면에서 비밀번호를 바꿀 수 있습니다.
- **사이트 매니저**: Supabase의 `managers` 표에 계정 값을 넣습니다(화면 표시용으로 `config.js`의 `managers`에도 같이 적기).
- **숨기기**: Supabase 관리 화면의 `projects` 표에서 그 줄의 `hidden`을 `true`로 바꿉니다.
- 좋아요와 조회는 로그인하지 않은 사람도 누를 수 있어서 브라우저 무작위 값으로 셉니다. 여러 번 누르는 것을 완전히 막지는 못합니다.
- 피드백(utterances)은 공개 저장소의 Issues에 남습니다. 비공개 결과물의 피드백도 마찬가지입니다.

## 예상 가치와 매니저

- 올라온 결과물마다 "예상 가치"가 붙습니다. 매니저가 달기 전에는 "요청 중", AI 분석을 수락하면 "분석 중"(30분이 지나면 다시 "요청 중"), 단 뒤에는 평가 금액과 개선 시 예상 금액이 보입니다.
- 매니저는 구글 로그인 계정 값으로 정합니다. `config.js`의 `managers`에 적은 계정은 사이트 매니저(모든 결과물), 방을 만든 사람은 그 방의 방장(그 방 결과물)입니다. 계정 값은 각자 `me.html` 아래쪽에서 볼 수 있습니다.
- 매니저는 `me.html`에서 "매니저 모드"를 켜고 끕니다(브라우저에만 저장). 켜면 상세 화면에 금액 직접 달기와 "AI 분석 수락하기"가 보입니다.
- AI 분석은 **매니저 자신의 Anthropic API 키**로 브라우저에서 Claude(`claude-opus-5-5`)를 바로 부릅니다(`anthropic-dangerous-direct-browser-access` 헤더). 운영자의 키는 사이트에 넣지 않습니다. 구조화된 출력(JSON 스키마)으로 받고, 거절되면 서버가 다른 모델로 다시 시도하도록 `fallbacks: "default"`를 켜 두었습니다. AI가 채운 값을 매니저가 확인한 뒤 "이 금액으로 달기"를 눌러야 기록됩니다.
- 기록(`분석 시작`, `분석 취소`, `AI 평가`, `가치 평가`)은 `record_value` 함수로 남기고, 서버가 매니저나 그 방의 방장인지 확인합니다. AI 분석이 끝나면 AI가 낸 금액과 코멘트를 바로 `AI 평가`로 남기고, 매니저가 "이 금액으로 달기"를 누르면 `가치 평가`(매니저 확정)가 됩니다. 매니저 확정이 없으면 카드에 "AI 예상 가치"로 보입니다.
- 결과물 화면 아래 "버전별 평가 기록"에 버전마다 마지막 평가를 펼쳐 보여 주고, 이전 평가는 접어 둡니다.

## 목록 모양과 버전

- 첫 화면과 방 화면의 공개 결과물은 `assets/board.js`가 그립니다. 맨 위에 "이번 주 새로 올라온 결과물"(최근 7일에 올라오거나 새 버전이 나온 것)을 테두리로 묶고, 그다음 좋아요 Top 4(1위 금, 2위 은, 3위 동, 4위 파랑 테두리), 그 아래 나머지를 좋아요 순으로 보여 줍니다. 나머지는 조회수 순, 가격 순(평가 금액, 평가 전은 맨 뒤), 업로드 순으로 바꿀 수 있습니다. 넓은 화면은 4열입니다.
- 버전: `projects`의 `parent`(처음 버전 번호)와 `changes`(바뀐 점)를 씁니다. 상세 화면의 "새 버전 올리기"는 처음 올린 사람이 같은 구글 계정으로 로그인했을 때만 보이고, 서버도 같은 계정인지 확인합니다.
- 버전을 묶으면 번호, 방, 공개 범위, 좋아요, 조회수는 v1을 따르고 내용은 최신 버전 것을 씁니다. 예상 가치는 버전마다 따로 달고, 지난 버전의 평가는 상세 화면의 버전 기록에 남습니다.

